# HYlight 基因密碼子最佳化與雙宿主分子選殖

1. 引用自哪篇 paper: fructose-biosensor-liver-cancer
2. Outline (任務主線): HYlight 基因密碼子最佳化與雙宿主分子選殖
3. Method: 
這一步要把 HYlight 感測器基因做成兩種「表現構築」，也就是能放進宿主、讓宿主照著造蛋白的 DNA。動作有四步。首先用序列設計軟體 (SnapGene) 對基因做密碼子最佳化：蛋白是一串胺基酸，每個胺基酸在 DNA 上可以用好幾組意思相同、拼法不同的三字碼寫出來 (同義密碼子)，而各物種偏好的拼法不一樣；最佳化就是在不更動最後蛋白的前提下，把基因改寫成細菌和人類「都」讀得順的折衷版，並在頭尾埋入幾個標準裁切點 (限制酶切位)。接著把設計好的序列交給廠商從零合成 (Twist Bioscience)。再用限制酶把基因剪下、貼進載體：限制酶是只認得特定短序列、就在那裡剪一刀的分子剪刀，剪完會留下能互相對上的黏性末端；在基因兩端埋「兩個不同」的切點，基因就只能以唯一正確的方向接進載體、不會裝反。最後逐字定序 (Sanger sequencing) 確認全程沒接錯、也沒抄錯。

兩個載體服務兩種需求。pQE-30 給細菌用：作者要在細菌裡大量造 HYlight 供體外實驗，因此在蛋白頭端接上六個組胺酸的標籤 (N 端 6×His-tag) 當作純化把手，方便下一步把它從一鍋雜蛋白裡專一釣出來。pCS2+ 則給人類細胞用，驅動 HYlight 於胞質表現供成像。關鍵是，兩個載體裝的必須是「同一條序列」的感測器：這篇論文要先在試管裡用純化蛋白量出一條 FBP 對應螢光比率的標準曲線，再拿去翻譯細胞讀數，而這招成立的鐵律，就是試管裡與細胞裡的蛋白得一模一樣，否則校正就失去依據。作者也一併做出 HYlight 的壞掉版本 HYlight Null——在第 152 號位置把胺基酸換成麩胺酸的點突變 (T152E)，剛好破壞掉抓 FBP 的口袋讓它抓不到 FBP，當作陰性對照；它必須走完全相同的選殖流程，才能和正常版互相比較。

有兩個步驟省不得。省掉密碼子最佳化，宿主碰到不熟的拼法會結巴、翻譯卡住，蛋白造得又少又不完整，純化和成像都會因訊號太弱而失敗；而且最佳化時也順手把基因內部不小心和裁切點撞名的序列改掉，免得那把分子剪刀連基因本身都剪爛。省掉逐字定序，合成或接合過程中偷偷混進的錯字就無人察覺，你會拿著一條「以為是 HYlight、其實帶了突變」的蛋白做完全部實驗，結論全部建在沙上。
4. 工具與材料: 
   - **密碼子最佳化 (codon optimization)**: 在不改變最終蛋白的前提下，把基因改寫成宿主偏好的同義密碼子拼法，以提高翻譯效率與表現量。
   - **限制酶切位 (restriction sites)**: 基因頭尾埋入的標準裁切點 (EcoRI/BamHI/HindIII/XhoI)，供限制酶剪出黏性末端、定向接進載體。
   - **pQE-30 載體與 6×His-tag**: 細菌表現載體，在蛋白 N 端加六個組胺酸標籤作為後續金屬親和純化的把手。
   - **pCS2+ 載體**: 人類細胞表現載體，驅動 HYlight 於胞質表現供成像 (Addgene #136466)。
   - **HYlight Null (T152E)**: 第 152 號位置換成麩胺酸的點突變，破壞 FBP 結合口袋、抓不到 FBP，作為陰性對照。
   - **Sanger sequencing**: 逐字定序法，確認合成與選殖後的序列正確無誤 (TubeSeq, Eurofins)。
   - **Twist Bioscience / SnapGene**: 分別為從零合成基因的廠商，與進行序列設計、密碼子最佳化的軟體。
5. 與此篇文章的關係: 
   在《Tracking fructose 1,6-bisphosphate dynamics in liver cancer cells using a fluorescent biosensor》這篇文章中，作者要用同一個 HYlight 感測器同時做試管內生化與活細胞成像。為此他們以密碼子最佳化做出細菌與人類雙宿主可用的表現構築，解決了「兩套系統若用不同序列、體外校正就套不回細胞」的瓶頸。它往上游取用 HYlight 原始設計 (Koberstein 2022)，往下游分別交出供純化的細菌質體與供成像的人類質體，是後續體外標準曲線能對應細胞讀值的前提。
