# Bulk RNA-seq 讀段比對與表現量化

1. 引用自哪篇 paper: car-neutrophils-cancer-immunotherapy
2. Outline (任務主線): Bulk RNA-seq 讀段比對與表現量化
3. Method:
   作者手上有兩批要比較的樣本——hPSC 衍生的嗜中性球，以及取自外周血 (peripheral blood, PB) 的成熟嗜中性球，第一步得把它們的定序資料變成可比較的數字。定序機器沒辦法一口氣讀完一整條長 RNA，它是把樣本裡所有 RNA 剪成幾百萬條「一小段一小段的序列」(讀段，reads) 分別讀出來的——因為現行技術一次只能準確讀出很短一截。麻煩是機器只給你這一大堆碎片，卻沒告訴你每段原本屬於哪個基因。所以第一步是把每段碎片「貼回」人類基因組上它原本的位置：hg19 是一份公開、被當標準的人類基因組底稿，比對軟體 (HISAT2) 拿你讀到的每段碎片去底稿上滑動、找出字母完全對得上的位置釘住，碎片一定位就知道它落在哪個基因。接著數每個基因收到幾段碎片、換算成表現量，最後得到一張大表：每個基因在每個樣本裡開得多強，這張表就是後面所有分析的原料。
為什麼不能直接用「每個基因收到幾段讀段」比高低，非得換算成 RPKM？因為直接數有兩個內建偏誤。第一，基因有長有短：同樣的表現強度，長基因天生被剪出更多碎片、收到更多讀段，光看數量會誤以為它較活躍。第二，每個樣本被定序的總量不一樣：定序做得深的樣本，每個基因讀段普遍都多，會假性整體偏高。RPKM 就是同時把這兩件事除掉——先除以基因長度、再除以樣本總讀段量，公式是 $\mathrm{RPKM}=\dfrac{\text{該基因讀段數}}{(\text{基因長度}/10^3)\times(\text{總比對讀段數}/10^6)}$。除乾淨後，不同基因之間、不同樣本之間的數字才真正可以並排比較。
作者為什麼比對到現成的 hg19、用 RefSeq 註解，而不自己從碎片重拼一份基因組？因為人類基因組早就被高品質定序、註解完整，每做一次實驗都重拼既慢又容易出錯。直接把碎片貼到現成的 hg19 底稿、再對照 RefSeq 這份「哪段座標是哪個基因」的清單，又快又標準，別人用同一套底稿做出來的數字還能直接跟你比。作者也刻意全程使用 HISAT2、rpkmforgenes.py 這類公開標準工具、沒有自寫程式，並把原始檔與 RPKM 結果存進公開資料庫 (NCBI GEO，GSE188393)，正是為了讓整個量化流程可被別人重現。
如果偷懶直接拿讀段數當表現量，長基因會被誤判成超級活躍、定序做得深的樣本會被誤判成基因整體都開很高，這些假訊號會一路帶進後面的聚類和通路分析，讓結論整個歪掉。另一個地雷是比對到錯的基因組版本：座標會對不上，本來屬於某基因的碎片被貼到別的位置，一開始的定位就錯了，後面再精細也沒用。所以「先正確比對、再雙重標準化成 RPKM」這一步看似枯燥，卻是後面所有分析可信的地基。
4. 工具與材料:
   - **讀段 (sequencing reads)**: 定序機器把 RNA 剪成的幾百萬條短序列，需事後貼回基因組定位。
   - **比對 (alignment / HISAT2)**: 把每段讀段對齊到參考基因組上最相符的位置，判斷它屬於哪個基因；本文用 HISAT2。
   - **參考基因組 hg19**: 公開、被當標準的人類基因組底稿，比對時的對照序列。
   - **RefSeq 註解**: 記錄哪段座標對應哪個基因的清單，用來把讀段歸到基因。
   - **RPKM**: 把讀段數同時除以基因長度與樣本總讀段量後的表現量單位，讓跨基因、跨樣本可比較。
   - **rpkmforgenes.py**: 計算 RPKM 的 Python 腳本。
   - **NCBI GEO (GSE188393)**: 公開存放原始 fastq 與 RPKM 結果的資料庫與登錄號，支撐可重現性。
   - **外周血嗜中性球 (PB)**: 取自外周血的成熟嗜中性球，作為 hPSC 衍生嗜中性球的比較對標。
5. 與此篇文章的關係:
   在《Engineering chimeric antigen receptor neutrophils from human pluripotent stem cells for targeted cancer immunotherapy》這篇文章中，作者要證明 hPSC 分化出的嗜中性球在基因表現上真的像成熟嗜中性球。第一步得把定序資料轉成可比較的數字：以 HISAT2 比對到人類基因組 hg19、再以 rpkmforgenes.py 量化成 RPKM 表現矩陣。它吃進原始定序碎片，產出可跨樣本比較的表現量大表，是後續聚類與 GSEA 的定量地基。
