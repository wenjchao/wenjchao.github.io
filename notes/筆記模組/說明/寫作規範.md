# 寫作規範

## 摘要
一個 `.md` 檔 = 一個模組；檔案分成「標題、摘要、內文」三段。這一頁是寫檔案時該遵守的規則、建議，以及會踩到的坑。

## 內文
### 檔案長相

```markdown
# 模組標題

## 摘要
一兩段話，說明這個模組在講什麼。可以多段、可以用粗體或條列，長度不限。

## 內文
正文。長度不限，可以自由使用 ##、### 分節，也可以裝其他模組：

[[另一個模組|摘要]]
```

解析規則（程式實際上怎麼切）：

1. **標題**：檔案第一個非空白行若是 `# 標題`，就是標題；沒有的話用檔名。標題只影響顯示，**連結永遠用檔名**。
2. **摘要**：從 `## 摘要` 這一行開始，到 `## 內文` 或下一個 `##` 標題為止。沒有 `## 摘要` 就代表這個模組沒有摘要——卡片上的「摘要」按鈕會反灰，不算錯。
3. **內文**：從 `## 內文` 開始到檔案結尾。內文裡的 `##`、`###` 都是普通標題，想怎麼分節都行。沒有 `## 內文` 的話，標題之後、摘要以外的所有內容都算內文。
4. 程式碼區塊（三個反引號包起來的區塊）與行內程式碼裡的 `## 摘要`、`[[...]]` 一律視為純文字。
5. `## 摘要`／`## 內文` 也接受 `## Summary`、`## 簡介`、`## 正文`、`## 內容`、`## Body`、`## Content`（不分大小寫，後面可加冒號）。要改名單就改 `index.html` 的 `CONFIG.summaryHeadings` 與 `CONFIG.bodyHeadings`。

### 檔名就是模組名

- `第一小點.md` 的模組名是 `第一小點`，連結時寫 `[[第一小點]]`。改檔名 = 改模組名，所有連到它的地方都要跟著改（見 [[說明/編輯]]）。
- 可以放進子資料夾：`專案/想法.md`。連結時寫 `[[專案/想法]]`，或只寫 `[[想法]]`（只要整個資料夾裡只有一個叫「想法」的檔案）。同一個資料夾裡的檔案互連，直接寫檔名即可。
- 檔名**不要**用這些字元：`|`、`[`、`]`、`#`（會跟連結語法打架），以及各作業系統不允許的 `/ \ : * ? " < >`。空格可以用，但建議用「－」或底線代替，比較好打連結。
- 大小寫不敏感：`[[readme]]` 找得到 `README.md`。但 macOS 與 Windows 本來就不區分檔名大小寫，Linux 與 GitHub 會區分，所以連結請照實際檔名寫。
- 入口：檔名叫 `首頁.md`（或 `index.md`、`README.md`）的模組會在打開檢視器時最先顯示。順序由 `CONFIG.home` 決定。
- 副檔名 `.md`、`.markdown`、`.txt` 都會被當成模組。不想被當成模組的資料夾（例如附件、程式碼），在裡面放一個空檔案 `.noteignore` 即可；以 `.` 開頭的檔案與資料夾、`node_modules` 會自動略過。

### 摘要怎麼寫才好用

摘要會出現在三個地方：卡片展開到「摘要」時、搜尋結果、以及別人快速掃過你的筆記時。所以：

- 用**一到三句**說清楚「這個模組回答什麼問題」，而不是重複標題。
- 可以放結論。摘要是給「不想展開全文的人」看的，先給答案。
- 小到不值得寫摘要的模組（例如只有三條條列的「第二小點」），就別寫，留空不是錯。

### 內文的 Markdown

用的是一般 GFM Markdown（標題、粗斜體、條列、編號、核取方塊、表格、引用、程式碼、連結、圖片），幾件要知道的事：

- **單一換行就會換行**（像 LINE 或筆記軟體），不必在行尾加兩個空格。不喜歡的話把 `CONFIG.markdown.breaks` 改成 `false`。
- 表格的欄位裡如果要寫 `[[模組|摘要]]`，直線要跳脫成 `[[模組\|摘要]]`，否則會被當成表格分隔。
- 想在文章裡「原樣顯示」`[[...]]`，用反引號包起來：`` `[[範例]]` ``。
- **數學式**：寫法和「什麼時候會被當成數學式」見下一節。
- 檔案開頭可以有 YAML frontmatter（`---` 夾起來的 `key: value`）。`title:` 會蓋過 `#` 標題，`summary:` 在沒有 `## 摘要` 時當摘要；`tags:` 與 `date:` 會顯示出來（見下一節）；其他欄位只儲存不顯示。
- 檔案請存成 UTF-8（大多數編輯器預設就是）。

### 標籤與日期

在檔案最開頭用 frontmatter 寫：

```markdown
---
tags: [心臟, 考試重點]
date: 2026-08-22
---
# 模組標題
```

`tags:` 接受 `[a, b]`、`a, b`、`#a #b`，或 YAML 清單（`tags:` 下面每行 `  - a`）；`tag:`、`標籤:` 也認得。`date:` 是自由文字，照原樣顯示（建議 `YYYY-MM-DD`，排序才對）。畫面上標籤顯示在標題下方，點一下就列出所有有這個標籤的模組；側欄底下的「標籤」節點列出全部標籤與數量；搜尋框打 `#心臟` 也一樣（可以再加文字：`#心臟 瓣膜`）。直觀編輯會保留 frontmatter，改標籤請切到「原始碼」。

### 數學式

寫法只有兩種：

- 句子裡的小式子：用一對 `$` 包起來，例如 `這就是 $E=mc^2$ 的由來` → 這就是 $E=mc^2$ 的由來。
- 自己占一段的大式子：用 `$$` 包起來，可以多行：

```markdown
$$
\Delta p = \tfrac{1}{2}\rho v^2
$$
```

（也接受 LaTeX 原生的 `\(…\)` 與 `\[…\]`。）裡面的語法就是 LaTeX：分數 `\frac{a}{b}`、上下標 `x^2`、`v_{lv}`、希臘字母 `\rho`、求和 `\sum_{i=1}^n`、矩陣……KaTeX 支援的都可以，不支援的指令會以原文紅字顯示，不會弄壞整頁。

**程式怎麼判斷一對 `$` 是不是數學式？** 它不看內容，只看 `$` 旁邊的字元。一對 `$` 要同時符合四件事才會被當成數學式：

1. 開頭的 `$` 後面緊接著的不是空白；
2. 結尾的 `$` 前面緊接著的不是空白；
3. 結尾的 `$` 後面緊接著的不是數字；
4. 兩個 `$` 在同一行，中間沒有別的 `$`。

四條都過才渲染；有一條不過，那個 `$` 就只是一個普通的美元符號。

用「價格 $5 和 $10」走一遍：第一個 `$` 後面是 5，不是空白，可以當開頭；往右找結尾，唯一的候選是 `$10` 前面那個 `$`，但它前面是空白（違反第 2 條），不能當結尾；這行再沒有別的 `$`，配對失敗，所以第一個 `$` 是美元符號。第二個 `$` 右邊已經沒有 `$` 可配，也是美元符號。整句都是純文字。

| 你寫的 | 結果 | 原因 |
|---|---|---|
| `$x$` | 渲染成 x | 四條都過 |
| `價格 $5 和 $10` | 原樣 | `$10` 的 `$` 前面是空白 |
| `我付$5，他付$10` | 原樣 | 第二個 `$` 後面接數字 |
| `NT$100` | 原樣 | 只有一個 `$`，湊不成一對 |
| `$ x $` | 原樣（不會渲染！） | `$` 旁邊有空白——要寫成 `$x$` |
| `` `$x$` `` | 原樣 | 在程式碼裡，一律不碰 |

這套規則是 Pandoc 的慣例，Obsidian 也是這樣判斷，所以檔案拿到別的工具開，結果一樣。

會被騙過的情況只有一種：數字後面接 `$`，例如 `$5 apples and 3$ pears`——開頭 `$5`、結尾 `3$` 四條都過，中間會被當成數學式。中英文都很少這樣寫；真的需要時把那個 `$` 寫成 `\$`，或在 `index.html` 的 `CONFIG` 把 `math` 設成 `false` 整個關掉。

### 建議的組織方式

- **一個概念一個檔**。模組可以被很多地方引用，拆小一點重用性才高；拆太碎的話，用一個「總覽」模組把它們用 `[[x|摘要]]` 串起來就好。
- **大綱先行**：在總覽模組裡先寫一排 `[[主題一]]`、`[[主題二]]`，再逐一點開建立。
- 想看某個模組被誰引用，卷到該模組最下面的「被引用於」。
- 左下角出現「N 個壞連結」時，點進去看哪些連結指向不存在的檔案。
