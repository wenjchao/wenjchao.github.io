# 規格書

## 摘要
「筆記模組」的需求、設計決策、檔案與連結的正式規則、各種載入來源的能力、同步架構、設定項與非目標。零散的要求都收在這裡；改規格請先改這份，再改程式。版本 1.3.20（2026-08-30）。

## 內文
### 1. 目標與範圍

**一句話**：每個 Markdown 檔是一個「模組」（標題＋摘要＋內文），模組之間用連結互相「裝進去」，讀的時候可以決定每個被裝進來的模組要顯示到哪一層。

**背景**：使用者對 Notion／Obsidian 的版面不滿，不需要花俏功能，需要一個好的「筆記單位」。所有筆記都用同一種模組表達。

**範圍內**：檔案格式、連結語法、檢視器（含編輯）、載入方式、打包與部署工具、文件。
**範圍外**：帳號、同步服務、即時協作、資料庫、外掛系統。

### 3. 設計決策與理由

| 編號 | 決策 | 理由 / 被捨棄的選項 |
|---|---|---|
| D1 | 檔名即模組 id；標題只影響顯示 | 連結穩定、不需要額外索引檔。捨棄：frontmatter id、自動 slug |
| D2 | 切法用 `## 摘要`／`## 內文`（使用者選擇） | 結構明確。另兩案（`---` 分隔、frontmatter）仍可由 `CONFIG.format` 與 frontmatter 相容 |
| D3 | 連結語法 `[[目標\|模式\|顯示文字]]`；`![[x]]`＝全文 | 與 Obsidian 習慣接近，純文字可讀；未知的第二段視為顯示文字，維持 Obsidian 別名相容 |
| D4 | 獨立一行＝卡片、句中＝晶片 | 區塊與行內在版面上本來就不同；晶片按 ▾ 仍可就地展開，不損失功能 |
| D5 | 顯示模式是「初始值」，讀者可改 | R3 的「手動展開」 |
| D6 | 循環引用：上層已展開者最多顯示到摘要；深度上限 10 | 允許互相引用又不會無限展開 |
| D7 | 單一 `index.html`，無建置工具、無框架；只內嵌 marked 與 KaTeX（皆 MIT） | 雙擊就能用、能寄給別人、十年後還開得起來 |
| D8 | 來源抽象層：Embedded／Folder／Files／Cache／Http | 同一份檢視器應付 R7 所有環境；新增來源只需實作小介面 |

| D14 | 資料夾裡放 `.noteignore` 即整個略過 | 區隔附件、程式碼、開發檔，三個走訪器（檢視器、serve.py、build.py）規則一致 |

### 4. 模組檔案格式（正式規則）

```
模組      := [frontmatter] [標題行] 內容
frontmatter := "---" NL (key ":" value NL)* "---" NL        ; 只在檔案最開頭
標題行    := "# " 文字 NL  |  文字 NL "="+ NL                 ; 第一個非空白行
內容      := 前段 [摘要段] [內文段]
摘要段    := "## " 摘要標題名 NL 行*                           ; 到 "## 內文" 或下一個 "## " 為止
內文段    := "## " 內文標題名 NL 行*                           ; 到檔案結尾
```

- 摘要標題名 ∈ `CONFIG.summaryHeadings`（摘要、summary、簡介、abstract），內文標題名 ∈ `CONFIG.bodyHeadings`（內文、正文、內容、body、content）；不分大小寫，允許結尾冒號。
- 解析結果 `title`：frontmatter `title` → 標題行 → 檔名（不含副檔名、不含資料夾）。
- `summary`：摘要段內容；若無摘要段且 frontmatter 有 `summary`，用之。
- `body`：內文段內容；若無內文段，則為「前段＋摘要段以外的所有內容」。
- 圍欄程式碼（三個反引號或三個波浪號圍起來的區塊）內的任何行都不參與切分。
- 其他 frontmatter 欄位保存在 `meta`（目前不顯示）。
- 編碼 UTF-8；接受 BOM；接受 CRLF。
- 寫作準則（R31、R51、R52、R55、R68）：摘要＝**用 10% 的文字表達 90% 的資訊**——寫架構與結論（有哪幾類、怎麼決定），細節與語法放內文；精簡＝字少話直白，不是塞縮寫與符號；**沒有新資訊的句子連內文都不放**（拿掉不會少懂什麼＝直接刪，不是移到內文）；沒有摘要就整段不寫（不硬編）；內容少的模組整份放內文、摘要留空、連結用 `全文`；列點一行一件事；切模組看三件事——會被別處引用、字數夠多、內容夠獨立，太短的往回併（單篇 ≤1500 字、列點 ≤3 層，超過就切）。
- 副檔名 `.md`、`.markdown`、`.txt`。略過：以 `.` 開頭的檔案／資料夾、`node_modules`、含 `.noteignore` 的資料夾。
- 模組 id = 相對路徑去副檔名，Unicode 正規化為 NFC，`/` 分隔。

### 5. 連結語法（正式規則）

```
連結   := ["!"] "[[" 目標 ["#" 錨點] ("|" 參數)* "]]"
參數   := 模式 | 外觀 | 顯示文字 | 其他    ; 第一個符合模式別名的參數是模式；第一個符合外觀別名的是外觀；第一個都不是的參數是顯示文字；其餘存入 opts
模式別名 := 1|標題|title|t | 2|摘要|summary|s | 3|全文|內文|full|body|f|all
外觀別名 := 卡片|card（預設） | 扁平|flat | 群組縮排|群組|縮排|group
```

- 沒寫模式：`CONFIG.defaultMode`（預設 1）；`!` 前綴：3。沒寫外觀：卡片。參數順序不拘：`[[x|扁平|摘要]]` 與 `[[x|摘要|扁平]]` 相同。
- 目標不得含 `[`、`]`、`|`、換行。錨點目前解析但不使用。
- 區塊／行內判定：`[[...]]` 所在行除最多 3 個前導空白與尾端空白外沒有其他字元 → 區塊卡片；否則行內晶片。列表項目內亦適用。
- 一般 Markdown 連結 `[文字](路徑.md)` 視為「只顯示標題」的連結（不產生卡片），並計入反向連結。
- 程式碼區塊與行內程式碼中的 `[[...]]` 不解析。
- 數學：`$$…$$`／`\[…\]` 獨立成段為區塊；`$…$`／`\(…\)` 為行內，開頭 `$` 後不得接空白或 `$`，結尾 `$` 前不得為空白、後不得接數字，內容不得含換行或反引號（否則孤立的 `$` 會跨過後面的行內程式碼配對；0.5.2 修正，`[[…]]` 同樣不得含反引號）。由 KaTeX 渲染（`throwOnError:false`），`CONFIG.math=false` 可關閉。標題中的 `$…$` 亦渲染。
- 表格儲存格中須寫 `\|`。

**目標解析順序**：完整 id → 相對於目前檔案資料夾 → 不分大小寫 id → 檔名（多個時取路徑排序最前）→ 標題 → 找不到。

### 6. 顯示行為

- 模式 1 標題、2 標題＋摘要、3 標題＋摘要＋內文。無摘要的模組：模式 2 的按鈕停用；初始要求 2 時顯示 1；互動要求 2 時視為 3。
- 展開鍵（▸）在 1 與「上次的非 1 模式」之間切換；段控鍵直接指定。
- 晶片：按文字導覽至該模組；按 ▾ 在所屬段落之後插入卡片，模式為 max(連結模式, `CONFIG.inlineExpandMode`=2)。
- 循環：卡片祖先鏈（含根模組）已包含該模組 → 標「循環引用」、模式上限 2。深度 ≥ `CONFIG.maxDepth` → 標「深度上限」、模式上限 2。
- 卡片帶 `data-depth`（1 起）與 `data-rail`（1–4 循環），供樣式上色。
- 被連結的模組標題一律粗體：卡片標題（`.card-title`）與晶片文字（`.chip-go`）用內文字體（`--font-body`，黑體）字重 700，五種樣式不得覆寫成更細或換回明體（R20）。
- 展開狀態寫進檔案（R22、D26）：來源可寫入時，使用者按卡片的 標題／摘要／全文 或 ▸ 後約 0.6 秒，檢視器改寫父模組檔案裡對應的 `[[…]]`（只換模式字；`![[x]]` 要改成非全文時改寫成 `[[x|模式]]`；顯示文字、外觀、其他參數保留），存檔後重新解析、重畫並保留捲動位置。同一個父模組在 0.6 秒內的多個改動合併成一次存檔。改寫前後都用 lexer 驗證（連結數相同、只有目標連結的模式改變、目標連結原文和畫面上的一致），不通過就不存並 toast 提示。晶片就地展開的卡片、「全部展開／收合」不寫檔。
- 展開狀態記憶（唯讀來源的退路，D24）：來源不能寫入時，使用者改了卡片模式、展開晶片後，與預設不同的部分記在 `cards` 鍵（每頁一筆：`{modes:{鍵:模式}, chips:{鍵:模式}, t}`），下次顯示同一頁時在建好卡片後依鍵還原；工具列「回到預設」（只在這種情況出現）刪除該頁記憶並重畫；記憶最多保留 400 頁。
- 扁平外觀（R26、D27）：`data-style="flat"` 的卡片沒有外框與底色、沒有左邊距，清單的圓點或號碼照舊；標題一般字重、滑鼠移過顯示虛線底線；標題後面是實心粗箭頭（`ICON.triBold`，強調色，展開時轉 90°）；摘要與內文縮排在標題底下並有淡色左線；控制鈕（標題／摘要／全文／扁平／✎）滑鼠移過或聚焦才出現。扁平晶片：沒有底色與外框，文字同內文顏色加虛線底線，後面是小 ▾。
- 外觀切換（R27、R50）：每張卡片的工具列在「標題／摘要／全文」段控鈕旁有第二組段控鈕「卡片｜扁平｜群組縮排」，目前的外觀反白；按另一個立即換外觀，並依 D26 的規則把連結的外觀字寫回檔案（`[[x\|摘要]]` ↔ `[[x\|摘要\|扁平]]`），唯讀來源則記在 `cards.styles`。晶片不提供切換。
- 併回（R47、D42）：可寫入且來源能刪檔時，卡片工具列多一顆「併回」——確認後把該模組的標題＋摘要＋內文搬回這個連結的位置（相對路徑改寫）、刪除模組檔；其他模組還連著它、有子模組、有 frontmatter 時會先列出提醒。晶片就地展開的卡片不提供（對不到檔案裡的連結）。
- 清單項目裡的卡片（D28）：`li` 的第一個子元素是卡片時，瀏覽器原生的號碼／圓點關掉，改由 CSS 依 `.card-head[data-n]` 畫在標題列左邊的框外（編號清單：`N.`，含 `start`；項目清單：實心圓點），扁平與一般卡片都一樣，位置與同清單其他項目的原生號碼對齊；卡片在清單裡的上下外距縮為 6 px（扁平 0.15 em）。
- 根模組頁面：（麵包屑列：軌跡／上層，R36）標題、日期（frontmatter `date`）、更新時間、字數、子模組數、標籤（點了篩選）、摘要、內文、「被引用於」。
- 核取方塊（R38、D35）：來源可寫入且不在編輯器裡時，畫面上所有 `- [ ]` 都能點，點了約即時寫回所屬模組（巢狀卡片裡的寫回被裝進來的那個模組）並重畫（保留展開狀態）；唯讀來源維持不可點。
- 搜尋高亮（R39）：搜尋框有字時，目前頁面裡命中的字以 `mark.hl` 標起來；搜尋字改變就重畫。
- 「全部展開／全部收合」作用於目前頁面所有卡片（受循環與深度限制）。
- 檔案變動後重新渲染時保留：每張卡片的模式、晶片展開、捲動位置。
- 找不到的目標：區塊顯示虛線方塊、行內顯示虛線晶片；來源可寫入時可一鍵建立。
- 特殊頁 `#/__links`：列出所有壞連結與其引用來源。

### 7. 來源與能力

| 來源 | 偵測 | 讀 | 監看 | 寫 .md | 寫圖片 | 備註 |
|---|---|---|---|---|---|---|
| Embedded | 頁面內有 `<script type="text/x-module">` | ✓ | ✗ | ✗ | ✗ | build.py 產物 |
| Http | `api/modules` 或 `modules.json` 存在 | ✓ | ✓（2 s／60 s） | serve.py ✓；GitHub token ✓（D39） | serve.py ✓；GitHub token ✓ | manifest 可含 `text`、`github`；有 `github`＋token → 直接編輯 |
| Folder | 使用者按「匯入資料夾」 | ✓ | ✓（2 s） | ✓ | ✓ | 目錄 handle 存 IndexedDB |
| Files | 拖放／檔案選取 | ✓ | ✗ | ✗ | ✗ | 結果寫入快取 |
| Cache | 以上皆無且快取存在 | ✓ | ✗ | ✗ | ✗ | 僅文字 |

偵測順序：Embedded → Http → 已授權的 Folder → Cache（若有未授權的 Folder 記憶，顯示「重新連接」提示）→ 歡迎頁。

儲存（每個 html 路徑一份，鍵值前綴 `nm::<origin+pathname>::`）：`dirHandle`（Folder 的目錄 handle）、`cache`（模組文字、匯入時間；檔案匯入另含 ≤ 20 MB 圖片 blob）、`theme`、`style`、`last`、`cards`（唯讀來源下每頁的展開狀態，D24）、`tree`（側欄展開的節點，R24）、`editMode`（上次用的編輯模式：`wysiwyg`／`source`／`split`）、`draft::<模組 id>`（自動儲存的草稿 `{text, t, base}`，R41）、`ghToken`（GitHub 直接編輯的 token，R43；「停用直接編輯」即刪）。IndexedDB 不可用時退回 localStorage（僅文字，≤ 4 MB）。「忘記」= 刪除 `dirHandle`、`cache`、`last`、`cards`、`tree`、所有 `draft::` 並回到歡迎頁。

來源介面：`kind, label, writable, load() → {modules, assets}`；可選 `watch(onDelta)`, `stopWatch()`, `save(path, text)`, `saveBinary(path, blob)`, `remove(path)`（有它才出現「改名／搬移」「刪除」；Folder 與 serve.py 有）, `editUrl(path)`。

### 8. 編輯

- 進入：工具列「編輯」、卡片 ✎、新增模組、建立缺少的模組。
- 編輯列（R28）：進入編輯後，主區最上面是一條 `position: sticky` 釘在捲動區頂端的編輯列——左起「直觀編輯｜原始碼｜並排」段控鈕、格式鈕（原始碼模式隱藏）、右端「儲存」；上方普通工具列只剩檔案路徑與「取消」。唯讀來源沒有編輯列（只有「檢視原始檔」的工具列）。
- 三種模式（R25、R29、D23、D29），編輯列切換，上次用的記在 `editMode`（預設 `CONFIG.editorDefault`＝`wysiwyg`）：
  - **直觀編輯（所見即所得）**：三個區域——標題（單行）、摘要、內文——直接打字；工具列：粗體、斜體、底線、刪除線、螢光、標題（大／中／小／一般）、項目清單、編號清單、核取清單、引言、程式碼、連結、圖片、模組連結、數學式、表格、分隔線。模組連結（卡片／晶片）、數學式、圖片在編輯器裡是「原子」：不可在裡面打字，點一下可改（模組、模式、TeX）或刪除，序列化時原樣寫回 `[[…]]`／`$…$`／`![](…)`。行首打 `- `、`1. `、`# `～`### `、`> `、`[] ` 會自動變成對應格式。貼上純文字；貼上或拖入圖片照原規則存檔。Tab／Shift+Tab 在清單裡縮排／反縮排。
  - **原始碼**：原始 Markdown 文字框＋即時預覽（輸入後 180 ms 更新）；Tab 鍵插入兩個空格。
  - **並排**：左邊是直觀編輯的文件本體（標題、摘要、內文），右邊是原始碼文字框，沒有另外的預覽；兩邊各自捲動、高度填滿視窗剩餘空間（視窗改變大小時重算），窄於 820 px 時改上下堆疊。同步規則見 D29；格式鈕作用在左邊。
  - 三種模式互切時保留未儲存的修改（直觀→原始碼先序列化；原始碼→直觀重新解析；並排以最近打字那邊為準）。唯讀來源只有原始碼（檢視）模式。
- 儲存：`save()` → （直觀模式先序列化成 Markdown；並排模式取最近打字那邊）→ 寫檔 → 重新解析 → 更新索引與側欄 → 回到檢視。⌘/Ctrl+S。
- 序列化規則（直觀→Markdown）：輸出一律是正式格式 `# 標題`／`## 摘要`／`## 內文`（原檔若用別名標題或 `---` 切法會被正規化）；frontmatter 原樣保留在最前面；段落、標題、清單（含巢狀與核取）、引言、程式碼區塊、表格、分隔線、粗斜底刪螢光、行內程式碼、連結、圖片、`<sup>`／`<sub>`／`<kbd>` 都對應到 Markdown；段落內的換行寫成單一換行（`breaks: true` 下即換行）；會破壞語法的字元（`*`、`` ` ``、`[`、行首的 `#`／`-`／`>`／`1.`、`$`）自動加 `\`。要求：任何模組經「渲染→序列化→再渲染」後畫面相同（test9 用全部範例與說明文件驗證）。
- 外部修改偵測：未變更則直接載入（直觀模式重畫）；已變更則提示選擇。
- 連結自動完成（R35、D32）：三種模式都有；`Autocomplete` 清單固定在游標下方（視窗下緣不夠就翻到上方），Esc 關閉、失焦關閉。
- 草稿（R41、D37）：進編輯器若有不同於檔案的草稿 → 橫幅「還原草稿」「丟棄草稿」；儲存成功或取消放棄時清除。
- 改名／搬移／刪除（R34、R40、D31）：閱讀畫面工具列的「改名／搬移」（面板：新路徑、標題一起改、引用數提示）與「刪除」（confirm 列出引用數）；只在來源有 `remove()` 時出現。成功後跳到新 id；刪除後回首頁。
- 抽成模組（R47、D42）：編輯列上的「抽成模組」——選取內容 → 問名稱（預設取第一行）→ 內容搬進 `目前模組/名稱.md`、原位置換成 `[[連結]]`；新模組立即建檔，上層要記得儲存。三種模式都可用；直觀編輯以整個段落為單位。
- 新模組範本：`CONFIG.newModuleTemplate(name)`。
- 圖片：貼上或拖入 → `saveBinary()` 至 `dirname(模組)/CONFIG.imageFolder/時間戳-名稱.副檔名` → 插入 `![alt](相對路徑)`。
- 「取消」與離開頁面在有未儲存修改時先確認。
- 唯讀來源（Files／Cache／Embedded／Http 靜態）：「檢視原始檔」可看、複製、下載，不可存；工具列「唯讀？」說明原因與解法；有未授權的資料夾記憶時改顯示「重新連接後編輯」。
- 不提供：改名、刪除、搬移（交給檔案系統）。

### 9. 介面與操作

- 頂列：選單鈕（窄螢幕開側欄）、名稱（回入口）、狀態（來源 · 模組數 · 自動更新 · 可編輯／唯讀）、「匯入／來源 ▾」選單（重新連接、匯入資料夾（可編輯）、匯入檔案、匯入資料夾（唯讀）、重新載入、為什麼是唯讀、忘記）、樣式選單、深淺色。
- 側欄（R24、D22）：搜尋（比對標題、路徑、摘要、內文，不分大小寫；有關鍵字時顯示平面的符合列表）；沒有關鍵字時是樹狀列表——每個節點一列，有子節點的顯示箭頭，點箭頭展開／收起，點名稱開啟模組（純資料夾節點點名稱＝展開／收起）；同名模組與資料夾合併；入口模組置頂，其餘依 zh-Hant 排序（資料夾與模組混排）；開啟某模組時自動展開其祖先並捲到看得見；展開的節點記在 `tree` 鍵。樹的底下是「標籤」節點（有標籤時才出現）：展開列出每個標籤與模組數，點了等於在搜尋框打 `#標籤`。搜尋語法：空白分隔多個字全部要出現，`#標籤` 篩標籤，兩者可混用；結果列每項附命中片段。另有模組數、「N 個壞連結」、「＋ 新增模組」（可寫入時）。
- 模組工具列：返回、檔案路徑、全部展開、全部收合、回到預設（唯讀來源且有記憶時才出現）、列印，以及編輯／檢視原始檔／重新連接後編輯／在 GitHub 編輯（依來源狀態擇一）；可寫入且來源能刪檔時再加「改名／搬移」「刪除」。編輯中：工具列只有路徑與「取消」，其餘都在釘在頂端的編輯列（§8）。
- 通知列（主區最上方）：快取優先時的「重新連接資料夾」、唯讀原因；可關閉。短暫訊息用右下角 toast。
- 鍵盤：`/` 聚焦搜尋、Esc 清除搜尋或關閉選單、⌘/Ctrl+S 儲存、編輯器內 Tab 縮排。
- 版面（R23）：筆記區永遠滿版（視窗寬度減去側欄與邊距，不設上限）；寬度 ≤ 900 px 時側欄變抽屜；≤ 600 px 隱藏頂列狀態文字（移到側欄底部）並縮小邊距。列印樣式隱藏介面、保留卡片與當下展開狀態。
- 深淺色：跟隨系統，可手動切換並記住；五種樣式（ink／card／outline／sketch／tab）以 `data-style` 切換並記住。

### 10. 資料交換格式

- 內嵌資料塊（build.py 單檔、線上示範）：`<script type="text/x-module" data-path="相對路徑.md" data-mtime="毫秒" data-set="資料夾名" data-enc="base64">base64 內容</script>`；圖片 `<script type="text/x-asset" data-path="…" data-type="image/png">base64</script>`。插入點是 `index.html` 裡的 `<!-- @modules -->`。
- `modules.json`：`{"generated": 毫秒, "modules": [{"path", "mtime", "size", "text"?}], "github"?: {"owner", "repo", "branch", "dir"}}`；也接受純陣列。
- serve.py API：`GET /api/modules → {"writable": true, "modules": [...]}`；`PUT /api/file?path=<url-encoded 相對路徑>`，body 為檔案內容，回 `{"ok", "path", "mtime", "size"}`；`DELETE /api/file?path=…` 刪檔，回 `{"ok", "path"}`（1.0）；路徑限制在資料夾內、只接受 .md／.markdown／.txt 與圖片副檔名。
- 圖片路徑：Markdown 裡一律相對於該 .md 所在資料夾；檢視器依來源轉成 object URL（Folder／Files／Cache）、相對 URL（Http）或 data URI（Embedded）。

### 12. 輔助工具

- `serve.py [資料夾] [--port] [--host] [--no-open]`：`GET /api/modules`、靜態檔、`PUT /api/file?path=`（.md 與圖片）、`DELETE /api/file?path=`。
- `build.py [資料夾] [-o] [--title] [--no-images] [--max-image-mb]`：單一 HTML；`--manifest [--inline] [--github 帳號/倉庫] [--branch] [--dir]`：modules.json。
- `pages.yml`：push 後執行 `build.py --manifest --inline` 並部署到 GitHub Pages。自訂部署流程（例如放進既有網站）**必須保留這個重建步**（§13）。
- `發佈到GitHub.command`（`notes/` 內，macOS 雙擊）：commit Mac 的修改 → 合併 iPad／手機在 GitHub 上存的修改 → 重建 `modules.json` → push。流程與衝突規則見 §13。
- `notion2modules.py <頁面.html> <輸出資料夾> [--overrides] [--name] [--no-images] [--split-title]`：Notion HTML 匯出 → 模組（需要 beautifulsoup4、lxml）。規則：頁面 → 總覽；每個 toggle（任何深度）→ `<頁名>/<主題>/<子題>/….md`，父模組原位置放 `[[相對路徑|摘要]]`（和清單相鄰的用 `扁平`）；h3 後的散落段落 → 模組；摘要不自動產生（R31）——只來自 overrides.json 的 `summaries`，`--split-title` 才把「主題：重點」拆成標題＋摘要；圖片 → `<頁名>/圖片/`。細節見 說明/從 Notion 匯入。
- `啟動筆記.command`（macOS）／`啟動筆記.bat`（Windows）：雙擊等同 `python3 serve.py`。
- `開發/assemble.py`：把 `開發/src/*`、marked、KaTeX（含字型轉 data URI）組成 `index.html`。`index.html` 是產物，改程式請改 `開發/src`。

### 13. 同步架構（Mac ↔ GitHub ↔ iPad）

**適用情境**：筆記正本直接住在網站倉庫的 `notes/`（1.1.4 起），底下分主題（1.1.5 起，R46）：`notes/醫學筆記/`＝筆記內容、`notes/筆記模組/`＝工具本體與說明（跟著發佈，說明在網站檢視器看得到）；`notes/` 根目錄只有檢視器（index.html）、serve.py、啟動檔、發佈腳本、build.py、modules.json 與入口 `首頁.md`。`notes/筆記模組/from notion/`（Notion 匯出檔案庫，約 430 MB，內含 `.noteignore`）與 `notes/筆記模組/_to_delete/` 在 `.gitignore`——留在磁碟、不進 git、不上網站。參考部署：`wenjchao/wenjchao.github.io`，分支 `master`（腳本自動偵測），網址 `https://wenjchao.github.io/notes/`。iPad／手機在 Pages 版用 token 直接編輯（R43）；三邊修改的會合交給 git 合併（R44、R45、D41）。

**角色與真相源**

- `notes/` 資料夾＝**正本**，同時就是 git 的工作目錄——只有這一份，沒有副本。編輯用它：雙擊 `notes/啟動筆記.command`（本機伺服器），或瀏覽器「匯入資料夾」選它。
- git 倉庫＝歷史與運輸：Mac 靠發佈腳本 commit＋push；iPad 每存檔一個 commit（D39）。任何被合併蓋掉的版本都留在歷史裡（`git log -- notes/<檔名>`）。
- Pages 網站＝讀（每 60 秒輪詢 `modules.json`）＋寫（token）。`modules.json` 是產物：發佈時產一次、部署時一定重建，不手改。
- 認證兩套、互不相干：Mac 推送用 git 認證（GitHub Desktop 或 `gh auth login`，存在 Mac）；檢視器直接編輯用 fine-grained token（存在各裝置瀏覽器）。

**發佈流程**（`notes/發佈到GitHub.command`，macOS 雙擊）

1. `git add -A notes`（外加 `.gitignore`、deploy.yml）→ 有變化才 commit（「更新筆記＋日期」）。**只加這幾個路徑**——使用者放在倉庫其他地方的東西（`techniques/`、`.claude/`…）永遠不會被腳本收進 git。
2. `git pull --no-rebase -X ours` 合併 GitHub 上的修改（iPad 存的）。合併語意：不同檔案、同檔不同段落＝自動合併（比 1.1.2 的檔案級帶回更細）；**同一段兩邊都改＝保留 Mac 版**；一邊刪一邊改（modify/delete，`-X ours` 不自動解）＝腳本逐檔以「保留 Mac 的結果」收尾（`checkout --ours`；ours 是刪除時 `git rm`）並列出檔名。拉取失敗（沒網路）＝停止。
3. 重建 `modules.json`（`build.py notes --manifest --inline --github … --dir notes`），有變化再一筆 commit。
4. `git push`。被拒（推送期間 iPad 又存檔）＝再雙擊一次即可，會先合併再推。

**不變式**

- 每次部署必重建 `modules.json`（deploy.yml 的專屬步驟，`[ -f notes/build.py ]` 才執行）；缺這步，iPad 的 commit 永遠上不了網站（1.1.2 的洞 (1)）。
- 任一步失敗就停止並說明；內容沒變化就不 commit——連續雙擊安全（冪等）。
- 發佈腳本本身（`notes/發佈到GitHub.command`）在 `.gitignore`：不進 git、不會被部署到公開網站。
- 衝突一律「保留 Mac、列出檔名」，不靜默、不自動合出四不像；被蓋掉的版本在 git 歷史撈得回來。

**部署端（deploy.yml）**：push `master` 後——`scripts/build_index.py`（網站首頁）→ 重建 `notes/modules.json` → 複製最上層每個資料夾到 `_site`（排除 `_site`、`scripts`、`本地`）→ 部署 Pages。一般獨立倉庫用附的 `pages.yml` 即可。

**測試**：iPad 端（token、PUT／DELETE、sha、pending、「部署中」提示）由 test11 以假 Contents API 覆蓋；發佈腳本是 bash＋真 git 倉庫，沒有自動化測試——改動它之後人工驗一輪：只有 Mac 改、只有 iPad 改、同段衝突、一刪一改，各一次（技術債已登記）。

| 搬移不搬圖片 | 搬到別的資料夾後，圖片留在原資料夾，Markdown 用 `../舊資料夾/圖片/x.png` 指回去（D31） | 圖片多、想一起搬的，手動搬資料夾再全域取代；要自動搬得先處理同名與共用 |
| 只靠檔名找到的連結（解析第 4 步）改名後才被改寫 | `[[想法]]` 若本來就是靠寬鬆的檔名比對找到別的資料夾的 `想法.md`，改名時一樣會被改成新寫法（完整路徑）——這是對的，但檔案會因此從「短寫法」變「長寫法」 | 知道就好；寫完整路徑本來就比較穩 |
| 搜尋是子字串比對 | 沒有斷詞、沒有模糊比對、不搜 frontmatter 以外的欄位；大小寫不分；結果依路徑排序而非相關度 | 幾千個檔案或想要相關度排序時再建索引 |
| 核取方塊只認清單記號後面的 `[ ]`／`[x]` | 縮排四格的程式碼區塊裡若有同樣的行，數量會和 marked 的結果不一致 → 寫回前驗證失敗、toast 提示，不會改錯 | 用圍欄程式碼（三個反引號）就沒事 |
| 自動完成的直觀編輯版在 Safari 沒有自動測試 | contenteditable 的 selection 行為各瀏覽器略有差異；Chromium 驗過 | 出問題回報 HTML 樣本 |
| 草稿存 localStorage | 每個 html 路徑共用約 4–5 MB；幾百 KB 的模組連打幾十次沒問題，超大檔案可能存不進去（靜默失敗） | 真要保險就常按 ⌘S |
| GitHub 直接存檔的部署時差 | 存檔後 commit 立即成立，但公開網址要等部署（約 1–2 分鐘）；這台裝置靠 pending 保護不會倒退（1.1.2 起重新整理後若部署沒跟上會顯示「部署中」提示，跟上自動收掉），**別台裝置**在部署完成前看到的是舊內容 | 頁面每 60 秒輪詢，部署完自然跟上；要「即時」得換即時後端，非目標 |
| 每個有意修改＝一個 commit | 核取方塊連打會生一串 commit、每個 commit 觸發一次部署 | 歷史雜訊而已；在意就少在 Pages 版上連打，或回電腦改 |
| 「啟用編輯」的驗證只能驗到讀 | `GET /repos` 的 `permissions` 反映的是**使用者**對倉庫的權限，不是這把 token 被授與的權限——Contents 給成唯讀的 token 也會通過啟用，直到第一次存檔才吃 403 | 403／404 的錯誤訊息直接指路：到 token 設定把 Contents 改成 Read and write、不用重貼（1.1.1） |
| token 存在瀏覽器 localStorage | 拿到這台裝置的人可以讀出 token（權限僅該倉庫 Contents） | 用 fine-grained token、設到期日；裝置不安全就用完「停用直接編輯」清掉 |
| 假資料夾測試把 `說明/` 排除 | test3／6／7／9 的假 File System Access 資料夾只放根目錄模組與 `範例/`，說明文件不在裡面（首頁 裡連到 `說明/…` 的卡片會顯示「找不到模組」，不影響驗的項目） | 要驗說明文件在可寫來源下的行為時再加進去（會變慢） |
| 發佈腳本沒有自動化測試 | `notes/發佈到GitHub.command` 是 bash＋真 git 倉庫，合併語意（§13）靠人工驗證；bash 3.2（macOS 內建）限制：變數一律 `${VAR}`、避免全形字元貼著變數 | 改動腳本後人工跑一輪：只有 Mac 改／只有 iPad 改／同段衝突／一刪一改，各一次；若壞過一次，就寫一支用本機裸倉庫的測試腳本 |
| Notion 檔案庫沒有異地備份 | `筆記模組/from notion/`（約 430 MB 匯出與圖）在 `.gitignore`，只存在 Mac 磁碟 | 在意就自己備份一份（雲端硬碟／外接碟），或跟 Claude 說改成進 git |
