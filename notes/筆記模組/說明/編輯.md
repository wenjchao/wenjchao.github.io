# 編輯

## 摘要
內建編輯器有三種模式：「直觀編輯」（預設）像 Notion 一樣直接在排版好的頁面上打字、用工具列設格式，不必懂 Markdown；「原始碼」看 Markdown 原文加預覽；「並排」左直觀、右原始碼，兩邊即時同步。打 `[[` 會跳出模組清單；改到一半沒存會留草稿。改名、搬移、刪除在模組工具列做，連到它的連結會一起更新。任何文字編輯器也都可以改 .md。建議搭配 git 留歷史。

## 內文
### 內建編輯器

來源可寫入時（匯入資料夾、本機伺服器，或 GitHub Pages 版按「啟用編輯」輸入過 token——見 [[說明/載入與同步]]），每個模組的工具列有「編輯」，卡片右上角也有 ✎。進入編輯後，畫面最上面有一條**編輯列**，往下捲也會一直釘在頂端：左邊是模式鈕「直觀編輯｜原始碼｜並排」，中間是格式鈕（原始碼模式沒有），右邊是「儲存」；「取消」在更上面的路徑那一列。三種模式隨時可切，會記住你上次用哪一種：

**直觀編輯（預設）**：頁面分成三塊——最上面的標題、接著「摘要」、再來「內文」——直接在裡面打字就好，不用寫 `#`、`##`。

- 工具列：**粗體**、*斜體*、底線、刪除線、螢光、段落格式（大／中／小標題、一般文字）、項目清單、編號清單、核取清單、引言、程式碼、連結、圖片、模組、數學式、表格、分隔線。選好字再按，或先按再打。`⌘B`／`⌘I`／`⌘U` 也通。
- 行首直接打 `- `、`1. `、`# `（到 `### `）、`> `、`[] ` 再接空白，會自動變成清單、標題、引言、核取清單，和 Notion 的習慣一樣。Enter 兩次離開清單。清單裡 Tab／Shift+Tab 縮排／反縮排。
- **模組**：按工具列「模組」，搜尋要裝進來的模組、選顯示模式（標題／摘要／全文）、選要當獨立一行的卡片還是句子中的晶片、選外觀（一般／扁平——扁平放在清單裡會和其他項目平行，見 [[說明/連結語法]]）。放進去的模組在編輯器裡是一個不能在裡面打字的小方塊，點一下可以改或刪。數學式（∑）和圖片也一樣是「整塊」。
- 貼上或拖入圖片會自動存檔並插入（見 [[說明/圖片]]）；貼上文字時只貼純文字，格式請用工具列加。
- 存檔時編輯器把畫面轉回 Markdown 寫進 .md：固定寫成 `# 標題`／`## 摘要`／`## 內文` 的正式格式，所以原檔若是用別的寫法（例如 `## summary`）會被整理成正式格式；畫面上看起來一樣。會被誤認成語法的字（例如文字裡的 `*`、`$`）會自動加上反斜線。
- 打 `[[` 會跳出模組清單（標題或路徑含你打的字），↑↓ 選、Enter 或 Tab 插入、Esc 關掉。在空行上選，放進來的是卡片（摘要）；在句子中間選是晶片。
- 切到「原始碼」或「並排」再切回來，未儲存的修改都會保留。

**原始碼**：上面是原始 Markdown，下面是即時預覽；`Tab` 鍵插入兩個空格。想精確控制格式、或貼一大段 Markdown 時用這個。這裡打 `[[` 一樣會跳模組清單，選了補成 `[[模組名]]`（同一個資料夾只寫檔名，別的資料夾寫完整路徑），想要摘要或全文再自己加 `|摘要`。

**並排**：左邊是直觀編輯（標題、摘要、內文），右邊是原始碼，兩邊各自捲動、會按比例跟著捲。要手寫 Markdown 又想即時看效果、或想對照「這段直觀編輯出來的東西原始碼長什麼樣」時用這個。規則只有一條：**哪邊在打字就以哪邊為準**——右邊打字，停下來 0.3 秒左邊就重畫；左邊打字、貼圖、插模組，停 0.3 秒右邊的原始碼就更新；存檔取最後打字那邊的內容。格式鈕作用在左邊。視窗窄於 820 px 時改成上下排。

三種模式共通：

- `⌘/Ctrl + S` 儲存。
- 編輯中如果檔案被別的程式改了：你還沒動過 → 直接載入新版本；你已經改了 → 上方出現提示，讓你決定用外部版本還是繼續。
- 「取消」會放棄修改（有修改時會先問一次）。離開頁面前若有未儲存修改，瀏覽器會攔一下。
- **草稿**：編輯中每隔一秒自動把內容存進瀏覽器。關掉分頁、當機、不小心重新整理之後，再開同一個模組的編輯器，上方會出現「有 …… 自動儲存的草稿」——按「還原草稿」接著改，或「丟棄草稿」。草稿只在這台電腦的這個瀏覽器裡，存檔成功或按「取消」放棄時就會清掉。

唯讀來源（拖放、單一檔案、GitHub Pages）只有原始碼模式，可按「檢視原始檔」看 Markdown、複製全文或下載。

### 外部編輯器

任何能存 UTF-8 純文字的程式都可以，頁面會在 2 秒內更新：

- **VS Code**：打開整個資料夾，內建 Markdown 預覽，搜尋取代跨檔案很方便（改名時會用到）。
- **Typora、iA Writer、MarkEdit**：所見即所得或專注寫作。
- **Obsidian**：直接把這個資料夾當 vault 打開也行。`[[x]]` 寫法相同；差別在 Obsidian 把 `[[x|文字]]` 的第二段當顯示文字，這裡會先判斷它是不是模式名（標題／摘要／全文），不是才當顯示文字。Obsidian 的 `![[x]]` 在這裡等於全文。
- **iPad**：Textastic、Runestone、Working Copy 都能直接改 .md；或用 [[說明/載入與同步]] 裡的伺服器模式在瀏覽器編輯。

### 新增模組

三個入口，結果一樣（建立 `名稱.md`，內容是標題＋空的摘要與內文，然後打開編輯器）：

1. 左下角「＋ 新增模組」，名稱可含資料夾：`專案/想法`。
2. 先在別的模組寫 `[[新名字]]`，存檔後按那個虛線晶片。
3. 左下角「N 個壞連結」報告裡的「建立」。

### 改名、搬移、刪除

在檢視器裡做（來源要能寫入：匯入資料夾或本機伺服器）：模組工具列有「改名／搬移」和「刪除」。

- **改名／搬移**：輸入新的檔名，可以含資料夾（`專案/想法` → `封存/想法` 就是搬移）。按下去會：
  1. 把檔案寫到新路徑、刪掉舊的；
  2. **所有連到它的模組**裡的 `[[舊名…]]`（含一般的 `[文字](舊名.md)`）改成新寫法——同一個資料夾只寫檔名，否則寫完整路徑；面板上會先告訴你有幾個模組連到它；
  3. 搬到別的資料夾時，它**自己**內容裡只靠「同資料夾」找到的 `[[…]]`、還有圖片與 `.md` 連結的相對路徑也一起改寫（圖片本身留在原處，用 `../` 指回去）；
  4. 標題和舊檔名一樣的話，預設把 `# 標題` 一起改（面板上可以取消勾選）。
  任何一個連結對不上（例如檔案剛被別的程式改掉）就整個不做，不會改到一半。
- **刪除**：先告訴你有幾個模組連到它，確認後刪檔；那些連結會變成虛線「找不到模組」，圖片資料夾不會動。
- 還是可以在 Finder／檔案總管裡改名或搬移，只是連結不會跟著改：改完看左下角有沒有「N 個壞連結」，點進去逐一修；或在 VS Code 全域取代 `[[舊名` → `[[新名`。只寫檔名的連結（`[[想法]]`）在搬到子資料夾後通常還找得到（程式會用檔名比對），寫完整路徑的才會壞。
- 同名檔案放在不同資料夾時，`[[檔名]]` 會取路徑排序最前的那個。請避免同名，或一律寫完整路徑。

### 多人協作與版本

- 這套工具沒有帳號、沒有鎖定、沒有歷史紀錄；兩個人同時改同一個檔，後存的蓋掉先存的。
- 建議把資料夾放進 **git**：每個檔案都有完整歷史、可以 diff、可以多人 branch；搭配 GitHub 還可以直接用網頁編輯、用 Pages 發佈。
- 不想碰 git 的話，至少讓資料夾在 Time Machine／雲端硬碟的保護下。
