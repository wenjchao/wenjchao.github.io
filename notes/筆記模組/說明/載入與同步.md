# 載入與同步

## 摘要
1. 載入方式五種：匯入資料夾（Chrome／Edge，日常主力）、本機伺服器（雙擊 `啟動筆記.command`）、拖放（唯讀）、單一檔案（唯讀）、GitHub Pages（分享與跨裝置）。
2. iPad／手機：開 GitHub Pages 網址，按「啟用編輯」輸一次 token 就能編輯。
3. Mac 發佈上線：雙擊 `發佈到GitHub.command`。
4. 看到「唯讀」：按工具列的「唯讀？」查原因。

## 內文
### 能力總表

| 方式 | 瀏覽器 | 即時更新 | 可編輯 | 圖片 | 適合 |
|---|---|---|---|---|---|
| 匯入資料夾 | Chrome、Edge（桌面） | ✓ 每 2 秒 | ✓ | ✓ | 日常主力 |
| 本機伺服器 `serve.py` | 全部 | ✓ | ✓ | ✓ | Safari／Firefox、iPad 連電腦 |
| 拖放資料夾 | 全部桌面 | ✗ | ✗ | 一起拖的可以 | 臨時看 |
| 「檔案」多選 | iPad／iPhone Safari | ✗ | ✗ | 要一起選 | iPad 單機閱讀 |
| 單一檔案 `build.py` | 全部 | ✗（重打包） | ✗ | 內嵌 | 寄人、離線 |
| GitHub Pages | 全部 | ✓ 每 60 秒 | ✓（輸 token 後） | ✓ | 分享、跨裝置、iPad 編輯 |

### 匯入資料夾（File System Access API）

1. 雙擊 `index.html` →「匯入資料夾」→ 允許「檢視並編輯」。**只要匯入一次**。
2. 之後任何編輯器改檔，2 秒內更新；新增、刪除、改名同步到側欄。
3. 重開瀏覽器：先顯示上次內容（快取、唯讀），按上方「重新連接資料夾」恢復編輯。這是瀏覽器對 `file://` 的安全規定；「Allow on every visit」對 `file://` 常記不住，檢視器管不了。不想每次按→改用本機伺服器（`http://` 免權限、無提示）。
4. 權限只及這個網頁、這個資料夾。

只有 Chromium 系（Chrome、Edge、Brave、Arc…）支援；Safari／Firefox 用下面兩種。

### 為什麼只能看、不能編輯？

狀態列標「唯讀」→ 工具列「唯讀？」直接給原因與解法。整理：

| 狀態 | 原因 | 解法 |
|---|---|---|
| `…（快取）· 唯讀`＋「重新連接資料夾」提示 | 重開頁面後要再授權一次 | 按提示 |
| 拖放／「匯入檔案」進來（Chrome／Edge） | 這種匯入不給寫回 | 選單→「匯入資料夾…（可編輯）」 |
| Safari／Firefox 永遠唯讀 | 沒有寫入資料夾的 API | 雙擊 `啟動筆記.command`／`.bat` 開 localhost:8765；或用 Chrome／Edge |
| 每次都跳權限視窗，Allow on every visit 沒用 | `file://` 的持久權限常記不住 | 本機伺服器 |
| `啟動筆記.command`「無法打開」，放別的資料夾卻可以 | zip 解出的檔帶 macOS 隔離標記 | 右鍵→打開→打開（一次）；或 `xattr -d com.apple.quarantine 啟動筆記.command` |
| 匯入時選了「檢視」 | 只有讀取權限 | 重新匯入，選「編輯」 |
| 單一檔案版 | 快照 | 開 index.html 匯入原始資料夾 |
| GitHub Pages | 靜態網站預設唯讀 | 「啟用編輯」輸 token（見下）；或「在 GitHub 編輯」 |

### 每份 index.html 各自記憶

- 記憶（匯入的資料夾、快取、樣式、最後看的模組、展開狀態、側欄、編輯模式）綁在**這個 html 檔的路徑**。
- 管兩套筆記：`index.html` 各複製一份到各資料夾（改名也行），各自匯入、互不干擾。
- html 改名或搬家＝新頁面，重新匯入一次（舊記憶不消失，只是不再對應）。
- 「來源 ▾」→「忘記匯入的內容」＝清此頁記憶回到起點（.md 一個字不動）；同選單可重新匯入、重新載入。

### 本機伺服器 serve.py

最省事：macOS 雙擊 **`啟動筆記.command`**、Windows 雙擊 **`啟動筆記.bat`**，自動開瀏覽器；關終端機視窗＝停止。第一次「無法打開」→ 右鍵→打開→打開（zip 隔離標記，一次就好）。手動：

```bash
cd 筆記資料夾
python3 serve.py              # http://localhost:8765，自動開瀏覽器
python3 serve.py --port 9000
python3 serve.py ~/別的資料夾
python3 serve.py --host 0.0.0.0   # 同 Wi‑Fi 的 iPad／手機連 http://電腦IP:8765
```

純 Python 標準函式庫，免裝套件。任何瀏覽器可看、可編輯、可貼圖、可改名刪除。
`--host 0.0.0.0`＝**區網任何裝置無密碼讀寫**；只在信任的網路開，公共 Wi‑Fi 不要。

### 拖放／匯入檔案（唯讀）

整個資料夾拖進視窗，或選單「匯入檔案／匯入資料夾（唯讀）」。內容（含 20 MB 內圖片）進瀏覽器快取，下次開直接顯示（標「快取」）；檔案更新→再拖一次取代。

### iPad／iPhone

- **隨時能看能改**：GitHub Pages＋「啟用編輯」（見下節）。可「加入主畫面」。
- **在家、不經網路**：電腦 `python3 serve.py --host 0.0.0.0`，iPad 開 `http://電腦IP:8765`。
- **單機閱讀**：`python3 build.py` → 單檔 html，AirDrop 過去 Safari 開（圖片已內嵌）。
- **臨時看**：`index.html` 放 iCloud Drive，「選擇檔案」多選 .md。

### GitHub Pages

1. 整個資料夾推成 GitHub 倉庫（私有倉庫的 Pages 要付費方案）。
2. Settings → Pages → Source 選 **GitHub Actions**。
3. 附的 `pages.yml` 每次 push 自動 `build.py --manifest --inline` 產 `modules.json` 並部署。
4. 網址 `https://帳號.github.io/倉庫/`。放進既有網站的子資料夾也行：該資料夾要有 `index.html`＋`modules.json`，且**部署流程每次要重建 modules.json**——否則網頁上存的檔不會反映到網站。

#### iPad／手機直接編輯（GitHub 直接存檔）

工具列「**啟用編輯**」→ 輸一次 token → 這台裝置＝完整編輯器（直觀、並排、貼圖、改名搬移、核取方塊）。每次存檔＝一個 commit 推回倉庫；公開網址 1–2 分鐘後更新（自己這台立即）。

申請 token（一次，在要編輯的那台裝置上）：

1. [github.com/settings/personal-access-tokens/new](https://github.com/settings/personal-access-tokens/new)（Fine-grained）。
2. Repository access → **Only select repositories** → 勾筆記倉庫。
3. Permissions → Repository permissions → **Contents：Read and write**；設到期日。
4. Generate → 整串貼進「啟用編輯」。

token 只存在這台裝置的瀏覽器（選單「停用直接編輯」可清掉）。翻卡片（標題／摘要／全文）**不** commit——記在裝置裡。
不想用 token：工具列「在 GitHub 編輯」＝GitHub 網頁編輯器。

#### Mac 一鍵發佈（發佈到GitHub.command）

正本住在網站倉庫的子資料夾（如 `wenjchao.github.io/notes/`），**只有這一份**，Mac 和 iPad 改的都是它。雙擊 **`發佈到GitHub.command`**：

1. Mac 的修改 → commit；
2. 抓 GitHub 上的修改（iPad 存的）**合併**：不同檔、同檔不同段自動合；同一段兩邊都改→保留 Mac 版（iPad 版在 GitHub 歷史，撈得回）；
3. 重建 modules.json → 推送 → 約 1–2 分鐘上線。

什麼時候按：Mac 改了一批想上線、或想拿 iPad 的修改。連按兩次安全（沒變化不推）。資料夾裡隱藏的 `.git`＝版本紀錄本體，不要動。完整規則見 [[說明/規格書]]「同步架構」。

不用 GitHub：`python3 build.py --manifest` 後把資料夾丟任何靜態空間（Netlify、Cloudflare Pages、內網）。

### 各平台限制

- Safari／Firefox 不能直接開資料夾（無 File System Access API）→ `serve.py` 或拖放。
- Safari 的清單號碼由程式自畫；手寫 `<ol type="a">`、`reversed` 的卡片號碼照十進位。
- Chrome 每次重開瀏覽器要重新授權一次（一個按鍵）；之前先顯示快取（唯讀）。
- 記憶綁 html 路徑：改名搬家→重新匯入。Safari file:// 不給 IndexedDB→localStorage 只記文字、約 4 MB。
- file:// 直接開 `index.html` 讀不到旁邊的檔（瀏覽器安全規則）→ 一定要匯入或拖放。
- 單一檔案版＝快照，原檔更新要重打包。
- GitHub Pages 直接編輯：存檔＝commit＋部署（1–2 分鐘）；翻卡片不寫回；離手裝置記得「停用直接編輯」。
- Google Fonts 要網路，離線退系統字體；數學字型已內嵌（代價：index.html 約 800 KB）。

### 雲端硬碟同步

資料夾放 iCloud Drive／Dropbox／OneDrive，各電腦「匯入資料夾」讀同一份。注意：

- iCloud「最佳化儲存空間」會把檔案變雲端佔位檔→讀不到；Finder 右鍵「立即下載」或關最佳化。
- 兩台同時改同一檔→衝突副本 `xxx (衝突).md` 也會顯示成模組，看到就手動合併。
- 同步軟體分兩步寫檔→偶爾先讀到半截，2 秒後下一輪就正確。
- 內建與外部編輯器同時改同一檔：後存的贏；偵測到外部修改會提示，不代合併。

### 效能

- 每 2 秒掃一次資料夾。幾百檔沒問題；上千檔或慢的網路磁碟→調大 `CONFIG.pollMs`（如 10000）或 `.noteignore` 排除子資料夾。
- 「全部展開」渲染整棵樹；循環引用與 10 層上限擋無限，不擋「很大」。
- 單檔版內嵌圖片：HTML 超過十幾 MB 在 iPad Safari 明顯變慢。

### 安全

- `serve.py --host 0.0.0.0`＝區網無密碼讀寫；`127.0.0.1`（預設）只有本機。
- Markdown 裡的 HTML 原樣渲染：**打開別人的筆記資料夾＝執行對方的 HTML／JS**，只載入信任的內容。要嚴格→`MD.render()` 後接 DOMPurify。
- GitHub Pages 公開倉庫＝全世界可讀。

### 快取與隱私

- 「匯入資料夾」與拖放的快取存在這台瀏覽器（IndexedDB；Safari file:// 退 localStorage：只存文字、約 4 MB），不上傳任何地方；清瀏覽器資料或按「忘記」即清。
- 樣式、深淺色、最後模組、展開狀態、編輯模式、草稿、token 存 localStorage，依 html 路徑分開。
- 展開狀態：可寫入時**不用記憶**——切卡片直接寫回 .md（模式字會改），檔案就是真相；唯讀來源才記瀏覽器、只記動過的卡片，「回到預設」可清那一頁。
- 完全離線可用；唯一對外連線＝Google Fonts。
