# 擴充開發

## 摘要
給想改程式的人：檔案結構、程式分層（解析→索引→渲染→寫回→來源→編輯）、常見擴充點（新語法、新來源、新樣式、新頁面）、怎麼跑測試與重新組裝 `index.html`。

## 內文
### 檔案結構

```
筆記模組/
├── index.html          檢視器（單一檔案；由 開發/src 組出來）
├── serve.py            本機伺服器：列檔、讀檔、寫檔、刪檔 API
├── 啟動筆記.command／.bat   雙擊＝python3 serve.py（macOS／Windows）
├── build.py            打包成單一 HTML；或產生 modules.json
├── notion2modules.py   Notion HTML 匯出 → 模組
├── .github/workflows/pages.yml   GitHub Pages 自動部署
├── 首頁.md             入口＝說明總覽（根目錄唯一的模組）
├── 說明/               說明文件（每篇一個模組）
├── 範例/               筆記一、第一小點、第二小點、補充說明（範例模組，互相只用檔名連）
└── 開發/               （裡面有 .noteignore，檢視器會略過）
    ├── src/style.css   全部樣式，含五種主題的 token
    ├── src/app.js      全部程式
    ├── src/body.html   介面骨架
    ├── src/template.html  <head> 與字體
    ├── marked.min.js、katex.min.js／css、katex-fonts/   相依（MIT／OFL）
    ├── assemble.py     把 src 組成 ../index.html
    └── tests/          測試（test1–7、test9、test10.mjs 用 Playwright、test8_notion.py 純 Python、run.sh）
```

改小地方可以直接改 `index.html`（CSS 在 `<style>`、程式在最後一個 `<script>`，和 src 一字不差）。改比較多就改 `開發/src`，然後：

```bash
python3 開發/assemble.py      # 重新產生 index.html
```

兩邊不要同時改，以免互相覆蓋。

### 程式分層（app.js 由上到下）

| 區塊 | 職責 | 你最可能改的地方 |
|---|---|---|
| `CONFIG` | 所有可調參數 | 預設模式、標題別名、入口檔名、輪詢間隔、樣式清單 |
| `Util`、`h()` | 小工具、建 DOM | — |
| `Parse` | 把一個 .md 切成 `{title, summary, body, meta, links}` | 換切法（`CONFIG.format`）、支援新的 frontmatter 欄位 |
| `Refs` | 解析 `[[目標\|模式\|文字]]`，以及從全文抽出所有連結 | 新的連結參數（`opts` 已保留） |
| `Store` | 所有模組的索引：依 id／檔名／標題查找（`resolve`；`resolveStrict` 只認完整路徑與同資料夾）、反向連結、壞連結、標籤索引、圖片資源；`linkTarget()` 算「連到某模組最短又不會連錯的寫法」 | 新的查找規則 |
| `MD` | marked 設定與兩個擴充（區塊卡片、行內晶片） | 新的 Markdown 語法 |
| `Cards` | 卡片、晶片、找不到的佔位；`hydrate()` 把渲染後的 HTML 裡的佔位換成真的卡片，並把清單裡卡片的號碼放進 `data-n`（`numberListCards()`） | 卡片長相、新的顯示模式、新的外觀 |
| `Persist`、`Memory` | IndexedDB／localStorage 薄包裝；側欄樹的記憶、唯讀來源下每頁展開狀態的記憶 | 新的記憶項目 |
| `LinkWriter` | 把卡片的模式／外觀改動寫回父模組的 .md：掃原文找 `[[…]]` 候選、和 lexer 的連結順序對齊、改寫後驗證再存檔（0.6 秒合併） | 新的連結參數要一起寫回時 |
| `TaskWriter` | 核取方塊寫回：畫面上第 k 個 ↔ 原文第 j 個 `- [ ]` 行（同 LinkWriter 的對齊思路） | — |
| `Refactor` | 改名／搬移／刪除：`retarget()` 改寫其他模組裡的連結、`relocate()` 改寫搬移模組自己的相對路徑、`rename()`／`remove()` 串起來源的 save／remove | 改名要連動的新東西（例如別名） |
| `Drafts`、`Autocomplete` | 草稿（localStorage）；`[[` 自動完成的清單、鍵盤、游標位置 | 清單的排序規則、觸發字 |
| `Sources` | `Embedded`、`Folder`、`Files`、`Cache`、`Http` 五種來源 | 新來源（見下） |
| `Theme`、`Style` | 深淺色、五種樣式 | — |
| `Wysi` | 所見即所得：Markdown→可編輯 HTML（原子化）、HTML→Markdown 序列化、工具列動作 | 新的工具列按鈕、新的序列化規則 |
| `Editor` | 編輯狀態、三種模式（直觀／原始碼／並排）切換、並排同步的「最近打字那邊為準」、儲存 | — |
| `App` | 路由（`#/模組id`）、畫面（含麵包屑 `buildCrumbs`、標籤）、樹狀側欄（含標籤節點、搜尋片段 `snippet`、頁面高亮 `highlight`）、編輯器（`renderEditor` → 釘頂的編輯列 `buildEditorBar` ＋ `renderWysiwyg`／`renderSource`／`renderSplit`；`buildWysiDoc` 是直觀編輯的文件本體，直觀與並排共用；自動完成接在 `makeTextarea` 與 `buildWysiDoc`）、改名面板 `renamePanel`／`deleteModule`、歡迎頁、特殊頁（`#/__links`）、事件綁定 | 新頁面、新按鈕、新的編輯模式 |

資料流：來源 `load()` → `Parse.module()` 每個檔 → `Store.upsert()` + `reindex()` → `App.show(id)` → `buildRoot()` 用 `MD.render()` 產 HTML → `Cards.hydrate()` 把 `[[...]]` 佔位換成卡片（遞迴）。檔案變動時來源呼叫 `App.applyDelta()`，重新渲染但保留展開狀態與捲動位置（`captureState / restoreState`）。使用者改了卡片的模式或外觀：來源可寫入時 `App.onCardChange()` → `LinkWriter.queue()` 改寫父模組檔案裡那個連結並存檔（檔案就是真相）；唯讀來源才經 `App.remember()` 記進 `Memory`，下次 `show()` 時 `restoreMemory()` 還原。直觀編輯：`Wysi.field()` 把 Markdown 渲染進 contenteditable（`[[…]]`、數學式、圖片變成帶 `data-md` 的原子），存檔時 `Wysi.toMarkdown()` 走訪 DOM 寫回 Markdown；`test9` 用全部檔案驗證來回轉換後畫面相同。

### 擴充點

**新的連結模式或別名**：在 `CONFIG.modeAliases` 加 key。真正新的顯示方式（例如「只顯示前三行」）要改 `Cards.card()` 的 `ensure()` 與 `setMode()`。

**新的 Markdown 語法**：照 `MD` 區塊的 `block`／`inline` 兩個 marked 擴充寫第三個，`marked.use({ extensions: [...] })`。marked 的擴充 API 見 marked.js.org。

**新的來源**（例如 WebDAV、Dropbox API、GitHub API 直接寫入）：實作一個類別，介面很小：

```js
class MySource {
  kind = 'mine'; label = '顯示名稱'; writable = true;
  async load() { return { modules: [{ path, text, mtime }], assets: [{ path, url | file | handle }] }; }
  watch(onDelta) {}          // 可選：發現變動時呼叫 onDelta({ upserts: [{path,text,mtime}], removed: [path] })
  stopWatch() {}
  async save(path, text) { return { mtime, size }; }        // writable 時需要
  async saveBinary(path, blob) { return { handle? }; }       // 可選：貼圖需要
  editUrl(path) { return null; }                             // 可選：唯讀來源的「去別處編輯」連結
}
```

然後在 `App.init()` 的偵測順序裡加進去，或在歡迎頁加一顆按鈕呼叫 `App.useSource(new MySource())`。

**新的特殊頁面**（像「壞連結」報告）：`App.renderSpecial(id)` 依 `#/__名稱` 分派，照 `__links` 的寫法加一個分支。

**新的樣式**：見 [[說明/外觀樣式]]。

**伺服器端**：`serve.py` 只有四個路由（`/api/modules`、靜態檔、`PUT /api/file`、`DELETE /api/file`），加功能（例如全文搜尋 API）直接在 `Handler` 加方法；記得同步在 `HttpSource` 加對應呼叫。來源介面多了可選的 `remove(path)`：有它，工具列才會出現「改名／搬移」「刪除」。

### 測試

`開發/tests/` 有九支 Playwright 腳本（test1–7.mjs、test9.mjs、test10.mjs）和一支純 Python 腳本（test8_notion.py），覆蓋：標籤與日期、全文搜尋片段與高亮、核取方塊寫回、麵包屑、連結自動完成、草稿、改名／搬移／刪除與連結連動（test10；serve.py 版在 test2）、解析與三種模式、巢狀與循環、晶片展開、導覽與搜尋、卡片標題與晶片的粗體、扁平外觀與清單裡卡片的號碼、樹狀側欄與展開記憶、展開狀態寫回 .md、所見即所得編輯器（全部檔案來回轉換、打字與工具列、原子、三種模式互切、釘頂的編輯列、並排同步）、serve.py 編輯存檔與外部變動、假的 File System Access 資料夾（含 `範例/` 子資料夾）、快取還原、檔案選取、拖放、圖片貼上、壞連結報告、表格跳脫、樣式記憶、`--inline` 靜態模式、每份 html 各自記憶與忘記、數學式、唯讀說明，以及 `notion2modules.py` 的轉換規則（每個 toggle 一個模組、清單旁的 toggle 扁平併入、圖片相對路徑、overrides、預設不補摘要與 `--split-title`）。

```bash
cd 開發/tests
npm init -y && npm i playwright && npx playwright install chromium   # 第一次
python3 -m pip install beautifulsoup4 lxml                            # 第一次（test8 要用）
./run.sh
```

改完程式至少跑一次；新功能請補一段測試，照既有檔案的寫法即可。

### 設計原則（改的時候請維持）

1. **檔案就是真相**：所有狀態都在 .md 裡，檢視器不持有任何「只有它知道」的資料（快取、樣式選擇除外）。
2. **單一檔案、零依賴**：`index.html` 雙擊就能用；不引進框架、不需要 build 工具（`assemble.py` 只是把幾個檔案串起來）。
3. **連結就是嵌入**：模組之間只有「引用」一種關係；顯示到哪一層是讀者的決定，寫的人只給預設值。
4. **能不加就不加**：新功能先問「能不能用 CONFIG 或 CSS 解決」。
