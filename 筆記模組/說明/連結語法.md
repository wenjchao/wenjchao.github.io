# 連結語法

## 摘要
`[[模組名|模式|外觀|顯示文字]]` 的完整規則：模組名可以帶資料夾（`[[說明/寫作規範]]`）、三種顯示模式、卡片與晶片的差別、「扁平」外觀怎麼和清單項目平行、切換模式會寫回檔案、目標怎麼被找到、循環引用怎麼處理。

## 內文
### 寫法一覽

| 寫法 | 顯示 |
|---|---|
| `[[第一小點]]` | 只顯示標題 |
| `[[第一小點\|摘要]]` | 標題＋摘要 |
| `[[第一小點\|全文]]` | 標題＋摘要＋內文 |
| `[[第一小點\|全文\|另一個名字]]` | 用「另一個名字」當卡片標題 |
| `[[第一小點\|另一個名字]]` | 只顯示標題，但用自訂文字（與 Obsidian 的別名寫法相容） |
| `![[第一小點]]` | 等於全文（Obsidian 的內嵌寫法） |
| `[[第一小點\|扁平]]` | 扁平外觀：沒有框，標題像一般文字，後面接一個粗箭頭；放在清單裡就和其他項目平行（見下） |
| `[[第一小點\|摘要\|扁平]]` | 扁平，且預設展開到摘要（參數順序不拘） |
| `[文字](第一小點.md)` | 一般 Markdown 連結，也會在檢視器內開啟 |
| `[[說明/寫作規範]]` | 在子資料夾裡的模組：`資料夾/檔名`（不含 `.md`），幾層都可以：`[[CV new/Heart Echo/EF]]` |
| `[[寫作規範]]` | 只寫檔名也找得到（先找同一個資料夾，再找整個筆記資料夾裡叫這個名字的檔案；見下面「目標怎麼被找到」） |
| `[[../上一層的模組]]`、`[[/最上層的模組]]` | 相對於目前檔案所在資料夾的 `../`；開頭的 `/` 表示從筆記資料夾最上層算起 |

**模組名（目標）就是檔案的相對路徑去掉 `.md`**——`說明/寫作規範.md` 的模組名是 `說明/寫作規範`，側欄和網址列（`#/說明%2F寫作規範`）看到的都是它。資料夾名和檔名一樣可以用中文、空白。三種參數可以任意搭配：`[[說明/寫作規範|摘要|扁平|寫筆記的規則]]`。

模式可以用中文、英文或數字：`標題／title／1`、`摘要／summary／2`、`全文／內文／full／body／3`。名單在 `CONFIG.modeAliases`。外觀：`卡片／card`（預設）、`扁平／flat`，名單在 `CONFIG.styleAliases`。

（上表的 `\|` 只是因為寫在表格裡才需要跳脫，平常直接寫 `|`。）

### 卡片還是晶片？

- `[[...]]` **自己占一行**（前面最多三個空格）→ **卡片**：有外框、有 標題／摘要／全文 的切換鈕、可以一直往下巢狀。放在條列項目裡（`- [[x|全文]]`）也算自己一行。
- `[[...]]` 寫在**句子中間** → **晶片**：按文字進入那個模組；按右邊的 ▾ 在這一段下面就地展開一張卡片（至少展開到摘要，沒有摘要就直接全文），再按一次收回。

### 扁平外觀：和清單項目平行

五小點裡第三、四點是模組、其他是普通文字，想讓它們看起來一樣：

```markdown
1. 第一點
2. 第二點
3. [[小點三|扁平]]
4. [[小點四|扁平]]
5. 第五點
```

扁平的模組沒有外框，圓點或號碼照舊，標題用一般字重，後面接一個粗箭頭（展開時轉向下）；展開的摘要／內文縮排在標題底下，左邊一條淡線標示範圍；標題／摘要／全文 的按鈕滑鼠移過去才出現。每張卡片的工具列在「標題／摘要／全文」旁邊還有「卡片｜扁平」兩顆鈕，目前的反白，按另一個就換外觀，而且會像模式一樣寫回 .md（`[[x|摘要]]` ↔ `[[x|摘要|扁平]]`）。句子中間的 `[[x|扁平]]` 會變成沒有底色的純文字連結，後面一個小 ▾。從 Notion 轉過來時，和清單項目相鄰的 toggle 會自動用扁平並併進同一個清單。

### 顯示模式的行為

- 連結裡寫的模式是**預設值**，讀的人隨時可以按卡片右上角切換。來源可以寫入時（匯入資料夾、本機伺服器），你切換的結果會在半秒後**直接寫回 .md**：`[[x|摘要]]` 變成 `[[x|全文]]`，顯示文字、外觀等其他參數不動——所以展開狀態跟著檔案走，換電腦、用別的工具看都一樣。不寫回的只有兩種：工具列的「全部展開／全部收合」（閱讀用的暫時動作）和晶片的就地展開。唯讀的來源（單一檔案、GitHub Pages）改為記在瀏覽器裡，工具列會多一顆「回到預設」。
- 改寫前後程式會驗證連結數沒變、只有那一個連結的模式變了，才會存檔；萬一對不上（例如檔案剛被別的程式改掉）會提示你手動改。
- 「摘要」按鈕在該模組沒有摘要時會反灰；`[[x|摘要]]` 連到沒摘要的模組時，一開始只顯示標題，按 ▸ 展開會直接到全文。
- 卡片左側的粗線顏色代表巢狀層級（第一層、第二層……循環使用四種顏色），細節依樣式而異，見 [[說明/外觀樣式]]。

### 目標怎麼被找到

依序嘗試，第一個找到的就用：

1. 完整相對路徑（相對於整個筆記資料夾）：`[[專案/想法]]`、`[[說明/寫作規範]]`
2. 相對於**目前檔案所在的資料夾**：在 `專案/總覽.md` 裡寫 `[[想法]]` 會先找 `專案/想法.md`；`[[../別的專案/想法]]` 往上一層找；開頭 `/` 則固定從最上層找（`[[/首頁]]`）。附的範例就是這樣寫的：`範例/筆記一.md` 裡只寫 `[[第一小點]]`，找到的是 `範例/第一小點.md`
3. 不分大小寫的完整路徑
4. 只比對檔名：整個資料夾裡任何一個叫 `想法.md` 的檔案（有多個時取路徑排序最前面的——請避免同名）
5. 比對標題（`# 標題` 的文字）

所以寫連結時：同一個資料夾裡的互連只寫檔名最省事（整個資料夾搬家也不會壞）；連到別的資料夾就寫 `資料夾/檔名`。編輯器裡打 `[[` 跳出的清單、直觀編輯的「模組」鈕，插入時都會自動依這個原則寫成最短又不會連錯的寫法。用工具列的「改名／搬移」改模組名時，所有連到它的連結會一起改寫（見 [[說明/編輯]]）。

都找不到 → 虛線晶片／虛線方塊，標著「找不到模組」。來源可寫入時按一下就能建立該檔案。

### 循環與深度

- A 裝 B、B 又裝 A 是允許的。展開時若遇到上層已經展開過的模組，卡片會標「循環引用」，最多只能看到摘要，不會無限展開。
- 巢狀最多 10 層（`CONFIG.maxDepth`），超過會標「深度上限」。

### 被引用於

每個模組頁面最下方會列出所有連到它的模組（`[[...]]` 與 `[...](x.md)` 都算；寫在程式碼區塊裡的不算）。
